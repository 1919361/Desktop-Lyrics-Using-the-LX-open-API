# 沉浸歌词 · Wallpaper Engine 工程

把桌面上的 `lyrics.html`（LX Music / Any Listen 逐字歌词壁纸页）打包成了一个
**可调参数的壁纸引擎网页工程**。工程是自包含的，所有文件都在这个 `Lyrics` 文件夹里。

---

## 一、文件说明

| 文件 | 作用 | 要不要动它 |
|---|---|---|
| `project.json` | 壁纸引擎的工程定义 + **全部可调选项**（就是右侧那堆滑条） | 想加选项才改 |
| `index.html` | 壁纸入口。由 `lyrics.html` 自动生成，**不要手改** | ✖（重跑 build.js 会覆盖） |
| `we-glue.js` | 选项桥：把壁纸引擎的属性翻译成 CSS 变量 / 运行时补丁 | ✔ 想改行为改这里 |
| `we-glue.css` | 选项层的样式（全部写成 `var(--we-*, 原值)`） | ✔ 想改样式改这里 |
| `backpicture.jpg` | 默认背景图（换成同名文件即可换图） | ✔ 随便换 |
| `preview.jpg` | 壁纸引擎里显示的预览缩略图 | ✔ 可换 |
| `build.js` | 从 `..\lyrics.html` 重新生成 `index.html` | — |
| `scan-fonts.js` | 扫描系统已装字体，写进 `project.json` 的字体下拉框 | — |
| `fonts.json` | 扫描结果备查（哪个文件、中英文名、含不含汉字） | — |
| `make-preview.js` | 重新生成 `preview.jpg`（无头 Edge 截图） | — |
| `install-to-we.js` | 把整个工程复制进壁纸引擎的 `projects\myprojects\` | — |

**设计原则**：`lyrics.html` 一行都没改，它还是原来那个能双击打开的独立页面。
工程这边只在 `</head>` 前插了两行引用（`build.js` 干的），
由 `we-glue.js` 在 `lyrics.html` 自己的脚本**之前**执行，
所以它能拦下 `fetch` / `EventSource`、提前定义好 `wallpaperPropertyListener`，
并把用户属性写成 CSS 变量。

> 反过来，如果你在编辑器里改了参数，改动保存在 `myprojects\GLyricsImmersive\project.json`；

> 不想要了就直接删掉 `myprojects\GLyricsImmersive` 这个文件夹。

- **LX Music / Any Listen 必须开着「开放 API 服务」**（默认 `127.0.0.1:23330`）。

#### 字体这一组是怎么做的

壁纸引擎的属性面板是**静态**的 —— 选项列表写在 `project.json` 里，
运行时没法往后塞新条目（网页里也拿不到目录列表）。
所以"从系统扫描字体"走的是**生成**而不是**运行时枚举**：

```bash
node "C:\Users\1919361\Desktop\Lyrics\scan-fonts.js"
```

它会扫 `C:\Windows\Fonts` 和 `%LOCALAPPDATA%\Microsoft\Windows\Fonts`
（非管理员安装的字体在后者），直接解析每个字体文件里的 `name` / `cmap` 表，
拿到**中英文族名**并判断**含不含汉字**，然后把结果写进
`project.json` 的 `font_family.options`，同时落一份 `fonts.json` 备查。

| 你会看到 | 说明 |
|---|---|
| 列表开头 4 项 | 「跟随原样式」+ 三个通用族（无衬线 / 衬线 / 等宽） |
| 后面按「含汉字优先 + 常用字体优先」排 | 雅黑、思源、宋体、黑体、楷体… 排在最前 |
| 带 `· 无汉字` 后缀的 | 纯拉丁字体，选了中文会走兜底，一般不用 |
| 装了新字体之后 | 重跑一次 `scan-fonts.js` 刷新列表；原来选的那个如果没了会退回「跟随原样式」 |

这台机器上扫出来是 **217 个字体文件 → 123 个可用字族**，其中 35 个含汉字。

- **下拉里没有的字体**：用「自定义字体名」直接敲，任何已安装字体都认；
  也可以敲一整栈，例如 `"Source Han Serif SC", "SimSun", serif`。
- **没安装的字体**（下载来的 ttf）：丢进工程目录，用「字体文件」选它。
  工程是相对路径引用的，所以 `install-to-we.js` 复制过去之后照样能用。
- 选了字体之后，选中的族挂在栈首，**后面仍然拖着原页面的 body 字体栈** ——
  音符、emoji、生僻字的兜底行为和原来一样，字形覆盖只增不减。
  名字敲错也不会崩，安静回落成原样（这一条有实测，见验收 G6）。

>
> 实现上有个坑值得说一句：壁纸引擎是**先让页面加载、后下发属性**，

> 更糟的是重载后属性会先回到 `project.json` 的默认值，引擎再下发一次自定义地址，

> 重载后 hash 还在，`we-glue.js` 在页面自己的脚本之前就读回来，
> 于是第二帧起就用对地址，也不再来回重载。（实测见下）

## 五、实现要点（排查问题时看）

- **不碰原逻辑**：所有视觉覆盖都在 `we-glue.css` 里，写成
  `html body <选择器> { 属性: var(--we-xxx, 原值) }`。
  选择器加 `html body` 前缀是为了压过原样式里的媒体查询；
  变量名和原值都能在文件里一眼对上。
- **默认值必须精确，不能"看着差不多"**：有几个默认值是原样式里某个颜色反算成
  0~1 小数得到的（例如强调色 `0.549 0.7843 1` = `rgb(140,200,255)`）。
  写成 `0.55 0.82 1` 这类近似值，四舍五入后会差 1 个色阶，
  结果就是"什么都没调、但渲染和原版不一样"。验收脚本第 0 节专门盯这件事。
- **三处 CSS 管不到的地方，用 JS 打补丁**：
  1. **API 地址**是源码里的常量 → 代理 `window.fetch` 与 `window.EventSource`，
     把 `http://127.0.0.1:23330` 前缀换掉（壁纸引擎的网页宿主带
     `--disable-web-security`，`file://` 下直连 localhost 没问题）。
  2. **律动强度**：`#bgPulseLayer` 的 `opacity` 被原代码每帧写成行内样式，
     样式表压不住 → 把它包进一个只有 `opacity` 的壳 `.we-pulse-wrap`，
     用壳当总音量旋钮（内外相乘）。同时把原来的 `--pulse-k` 钉成 1，
     免得「有背景图就减半」被算两遍。
  3. **背景图的开关 / 换图**：直接改 `#bgPhoto` 的行内 `backgroundImage` 与 `opacity`，
     并在原页面自己的初始化之后再补两次，保证最后的决定权在选项这边。
- **字体的默认值写成 `inherit`**：`.lyric-line` 用 `var(--we-font, inherit)`、
  `.bg-char` 用 `var(--we-font-art, inherit)`。不选字体时这两个变量**根本不存在**，
  `inherit` 就等于继承原样，一个像素都不会变（第 0 节对照里 `font.*` 全部一致）。
  天际屏那层原页面压根没写 `font-family`（靠继承 body），
  正是补上这条 `inherit` 之后才敢动它的字体。
- **字体名要洗一遍**：`font-family` 的值是拼进 CSS 声明里的，
  用户敲进来的引号 / 分号 / 花括号会把整条声明弄坏，`cleanFont()` 一律去掉；
  通用族（`serif` 之类）不加引号。敲错名字不会崩，安静回落成原样。
- **调完选项要「重新居中」**：改字号 / 行高 / 左右留白之后，每行的高度和间距都变了，
  正在唱的那一句会偏出屏幕中心，要等下一句才回来。原页面自己在 `window` 的 `resize`
  里重建内边距并把当前行滚回正中，所以 `we-glue.js` 在写完全部变量后
  **等两帧**（第一帧提交样式、第二帧布局已更新）再派发一个 `resize`
  —— 立刻派发的话，页面 handler 读到的还是旧布局，量出来的目标就偏。
  有了这一步，边放边拖滑条，当前那句始终留在正中。

### 验收

```
node ..\.workbuddy\check-we.js                    # 静态：属性 / 变量 / 开关类 / 注入顺序
node ..\.workbuddy\probe-we.js                    # 实测：无头 Edge + CDP
node ..\.workbuddy\report-we.js .workbuddy\we-probe.json   # 把结果翻译成人话（探针默认已直接输出）
```

`probe-we.js` 起一个本地 http 服务和无头 Edge，用桩数据顶掉 LX Music
（一首示例曲目 + 带逐字时间戳的歌词），然后把原版 `lyrics.html` 和工程的
`index.html` 放在同一浏览器里分别渲染、逐项比对计算样式。它跑八轮：

| 轮次 | 做什么 | 期望 |
|---|---|---|
| 0 | 工程默认 vs 原版 | 逐项完全一致（含净律动亮度峰值、逐字光晕、两个字体变量） |
| A | 工程默认快照 | 截图存档 |
| B | 全部属性推到上界 | 每一项都落到对应变量上 |
| C | 全部属性推到下界 | 9 个开关全部生效（扫光 / 间奏点 / 天际屏 / 光晕 / 高光 / 三件控件 / 变淡） |
| D | 复位成 `project.json` 声明的默认值 | 回到与原版一致 |
| F | 把字号改成 2.2× | 当前行仍在屏幕正中（偏差 < 4px） |
| G | 字体：换两个中文字体 / 自定义名覆盖 / 作用范围切换 / 乱写的名字 / 字体文件 | 见下 |
| E | 把 API 地址改成 `127.0.0.2:9999` | URL 留下 `#weapi=`、请求全部改道新地址、无报错、不来回重载 |

G 轮值得单独说一句：**光看 `font-family` 字符串是不够的** ——
名字写错时浏览器会静默回落，CSS 里照样写着那个名字。
所以每个用例都用同一个字串（`歌词宽度 Wg9 MMM ii 123`）在离屏元素里
按目标元素的计算字体量一次**实际字形宽度**：字体真生效了宽度就变
（默认 1262.41 → 宋体 1150 → 雅黑 1262.41），回落了就和原版一模一样。
乱写的名字那一档（G6）要的正是"宽度一点都不变"。
字体文件那一档会往测试目录拷一个系统字体当"用户自备字体"，
再用 `document.fonts.load()` 确认它**真的加载成功**了 ——
验的是"页面用上了文件里的字形"，不是"CSS 里写了这一行"。
（顺带一个坑：`document.fonts.check()` 对系统字体永远返回 `true`，
真名和乱写的名字都是 `true`，拿它当"名字存不存在"的判据会被骗。）

它会把 CSS 过渡临时关掉再测量：原页面有几处 0.5~1.4 秒的过渡，
测量时若正好落在过渡中间，读到的是插值而不是样式本身
（逐字光晕尤其明显，桩歌词每个字只唱 0.45 秒、而 `filter` 的过渡是 0.5 秒，
于是"正在唱的那个字"永远在过渡途中，跨页面比较必然对不上）。

调这个探针本身时，可以设 `WE_PULSE_FRAMES=10` 让律动采样从 400 帧降到 10 帧，
整轮快十几秒（此时峰值比较会自动跳过，因为 10 帧盖不满 5.5 秒的呼吸周期）。
